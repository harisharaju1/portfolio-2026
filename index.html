Senior Backend Engineer · agentic AI systems

I design agentic systems: AI that investigates, decides and knows when to hand off. That means specialist agents that choose their own tools and run in parallel, deterministic steps that keep the model out of decisions plain code can make, and human-in-the-loop review when confidence drops. All of it is measured, with evals that catch regressions, guardrails against prompt injection, and a cost on every agent run.

Underneath is eight years of backend engineering in C#/.NET and Node/TypeScript, now with Python. That's why the system around the model gets as much care as the model.

Selected work · 2026

doctriage: AI triage for insurance claim documents

Live

Upload a claim PDF. The service extracts the text, classifies the document with Claude, sends low-confidence results to a human review queue, and indexes the content for retrieval.

  • Confidence gate: a classification below the threshold goes to a review queue and is never stored as trusted until a person resolves it.
  • Versioned prompts and an eval harness: 20 hand-labelled fixtures, an LLM-as-judge on Bedrock, and pairwise comparisons run twice with positions swapped to cancel out position bias.
  • Cost per request, broken down by pipeline stage on /metrics, including calls that failed.
  • Three-layer prompt-injection defense, plus retries with backoff and a corrective retry when output fails schema validation.

codereview-agent: multi-agent pull request reviewer

In progress · week 3 of 4

A GitHub App that reviews pull requests. Specialist agents investigate the code with real tools and return typed, ranked findings with the cost of each review.

  • Built the agent loop by hand first: five tools (file reads, code search, dependency checks, and linting in three languages), then ported it to LangGraph with parity tests.
  • Multi-agent workflow: triage with no model calls, then security, performance, correctness and dependency specialists in parallel, then a deterministic merge.
  • Failure isolation: if one specialist times out, the review still comes back from the others, marked as partial.
  • A docs-only PR now costs $0.00 and takes 2.2 s. Before triage, it took 5 model calls and $0.02.

How I work

  1. Measure before I claim.

    I estimated a multi-agent review would cost $0.15–0.40. The real run cost $0.417, and the write-up says so, along with where the tokens went.

  2. Build it by hand before I reach for a framework.

    I wrote the raw tool-use loop before LangGraph, and my own retry utility before any library. That way I know what a framework is doing for me, and what it hides.

  3. Validate every boundary.

    Every LLM response and external API payload goes through Zod or Pydantic before anything uses it. Shape errors fail loudly at the edge.

  4. Write down the decision and the alternative.

    Each project has dated design notes: what I chose, what I rejected, and where I changed course from the plan.

  5. Mocks prove the logic, and real calls prove the integration.

    Two bugs only appeared against the live API, including a model ID with a date suffix that broke an exact-match price lookup. I keep a few paid end-to-end runs for that reason.
